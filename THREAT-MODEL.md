# Threat model

This file takes each trust boundary named in [SECURITY.md](./SECURITY.md) and applies the six STRIDE categories (Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege) to it. It complements SECURITY.md and does not repeat it: the boundaries, the scope and the accepted properties are defined there, and this file only records, per boundary and per category, what the threat is and what covers it. It was written on 2026-09-26 against the code at that date. Update it when a boundary changes, when a GAP closes (change its status and cite the mechanism, do not delete the row), and when an advisory is published (add the threat if it was missing). Ids are stable: never renumber, never reuse a retired id.

## How to read it

Every threat has one status:

- **MITIGATED**: a mechanism in the code or the pipeline covers it, cited by file and line or by symbol.
- **ACCEPTED**: it is one of the accepted properties in SECURITY.md, cited by label below.
- **OUT OF SCOPE**: it is one of the out-of-scope bullets in SECURITY.md, cited by label below.
- **GAP**: nothing covers it. A GAP carries a severity (what a realistic attacker or an unlucky operator gets) and the smallest fix. Where the fix says "or accept it explicitly", that is the maintainer's decision, not this file's.

A category with no credible threat says "none credible" and why, so it reads as considered rather than forgotten.

Labels for the SECURITY.md bullets cited below:

| Label | SECURITY.md bullet                                                                                                                    |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------- |
| A1    | Accepted: "A deploy script is arbitrary code."                                                                                        |
| A2    | Accepted: "`catchUnknownSigner` catches what rocketh cannot sign, and does not prevent an account it CAN sign for from broadcasting." |
| A3    | Accepted: "The interactive pasted-transaction check ranks evidence, it does not prove intent."                                        |
| A4    | Accepted: "The unknown-signer policy frame is dynamic scope over a sequential run."                                                   |
| A5    | Accepted: "The playground executes real deploy scripts in the reader's browser, by design."                                           |
| A6    | Accepted: "`linkedData` is public."                                                                                                   |
| A7    | Accepted: "Deployment records are trusted local input."                                                                               |
| O1    | Out of scope: "The documentation site"                                                                                                |
| O2    | Out of scope: "`demoes/`"                                                                                                             |
| O3    | Out of scope: "Advisories in third-party dependencies, on their own"                                                                  |
| O4    | Out of scope: "Anything that presupposes control of the operator's machine"                                                           |

File paths below are relative to the repository root. `environment/index.ts` means `packages/rocketh/src/environment/index.ts` and `executor/index.ts` means `packages/rocketh/src/executor/index.ts`.

## 1. The deploy script → rocketh

Not a boundary (SECURITY.md), so every category resolves to A1. Listed so the categories are visibly considered.

| Id       | Threat                                                                                                                            | Status   | Reference                                                                                       |
| -------- | --------------------------------------------------------------------------------------------------------------------------------- | -------- | ----------------------------------------------------------------------------------------------- |
| S-1      | A script, or any dependency it imports, sends a transaction as any account the config resolves.                                   | ACCEPTED | A1                                                                                              |
| T-1      | A script or dependency rewrites deployment records, artifacts or the environment object in the middle of a run.                   | ACCEPTED | A1                                                                                              |
| R (none) | None credible: scripts are developer-authored and versioned with the project, so "who ran what" is answered by the project's VCS. |          |                                                                                                 |
| I-1      | A dependency reads a `privateKey:` value from the config or `process.env` of the deploy process.                                  | ACCEPTED | A1, and "Keep the signing authority outside the deployment environment" in Production hardening |
| D (none) | None credible: a script that hangs or exhausts its own run harms only the run its author started.                                 |          |                                                                                                 |
| E-1      | An extension package's root exports become methods on every script's environment (`withEnvironment`) and run with its authority.  | ACCEPTED | A1 (extensions are config and dependencies)                                                     |

The boundary moves with the signer variant: in-process for `signerOnly`, on the other side for `wallet` and `remote`.

| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| S-7      | A named account is paired in config with a key or protocol for a different address, so rocketh signs as an address the script did not mean.                                                   | MITIGATED | The address of a key or protocol account is taken from the signer's own `eth_accounts`, not from the config (`environment/index.ts:639-640`, `:660`). |
| T (none) | None credible: for `wallet` and `remote` the approving side is authoritative by definition of the variant (CONTEXT.md, "signer"), and for `signerOnly` the fields the endpoint fills are T-8. |           |                                                                                                                                                       |
| R (none) | None credible: which human approved a Safe or HSM action is recorded by that authority; rocketh records only the hash it observed (R-1).                                                      |           |                                                                                                                                                       |
| I-3      | Key material held in-process for `signerOnly` is reachable by every dependency of the deploy process.                                                                                         | ACCEPTED  | A1, and the reason Production hardening says to keep privileged keys outside the process.                                                             |
| D (none) | None credible: a signer that never answers hangs a run with an operator present, and nothing is recorded before a hash exists.                                                                |           |                                                                                                                                                       |
| E-7      | A user-supplied `signerProtocols` entry is arbitrary code with access to every transaction and key it is given.                                                                               | ACCEPTED  | A1 ("their config").                                                                                                                                  |
