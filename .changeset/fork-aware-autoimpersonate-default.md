Auto-impersonation now defaults ON for a fork run, and stays off everywhere else. Impersonation is what makes an account rocketh cannot sign for executable on a node that supports it, so it is the only reason a Safe-owned step runs at all during a fork rehearsal; a fork with it off stopped at the first privileged call, which is the opposite of what someone forking mainnet wants to see. Only the LAST term of the resolution changed: an execution parameter still wins over the chain configuration of the network being SIMULATED, which still wins over the default, so an explicit `autoImpersonate: false` keeps turning it off and the unknown-signer deferral path stays exercisable on a fork exactly as before. A value configured on the forked network's chain entry is now honoured in both directions, including a `false`, which required the chain term to stop defaulting itself to `false` and start distinguishing "nobody configured impersonation" from "configured off". Nothing about the unknown-signer seam moves: `autoImpersonate` remains a node CAPABILITY resolved before the seam and `onUnknownSigner` remains the policy afterwards (`docs/adr/0006-unknown-signer-seam-and-orthogonal-autoimpersonate.md`), and the fork default gives the policy no new value.
