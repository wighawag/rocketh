A fork now has somewhere to state what makes it different from the network it forks: a `whenForked` sub-key on that network's own environment entry (`environments: {mainnet: {chain: 1, whenForked: {rpcUrl: 'http://127.0.0.1:8546', autoImpersonate: true}}}`). It is the same override bag as the existing `overrides`, layered on top of it and applied ONLY when the run is a fork, so the order is the forked network's `chains[<id>]`, then that environment's `overrides`, then the fork layer, most specific winning. Declaring it does not put a run into fork mode: a run is a fork because of how it was invoked, and on a plain run of the same environment the layer is ignored entirely. The local endpoint a fork dials is no longer read from `chains[31337]`, which is where a user configures their own dev node, so a dev node on a port of the user's choosing can no longer decide where a fork of another network is expected to listen; with nothing declared a fork dials the conventional local endpoint `http://127.0.0.1:8545` (exported as `CONVENTIONAL_LOCAL_RPC_URL`), which is where both anvil and `hardhat node` listen, so the zero-configuration case is unchanged and a fork no longer needs a local chain entry to have an endpoint at all. The type change is additive: `whenForked` is optional, and `environments[<name>].chain` is now optional too, so an entry may exist only to say where a fork listens.
