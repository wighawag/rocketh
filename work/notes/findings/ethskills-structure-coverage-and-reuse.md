# ethskills, read for the rocketh user skills

Researched for spec `agent-skill-for-rocketh-users`, to decide whether rocketh's user-facing skills should be contributed to ethskills, referenced from it, or written separately. Every claim below names the file or page it was read from. Paths without a host are in the ethskills repository at `47779e7`.

## Structure

- **Many small skills, one catalogue.** One directory per topic, each holding a single `SKILL.md` with `name` and `description` frontmatter: `why`, `ship`, `crops`, `protocol`, `gas`, `wallets`, `l2s`, `standards`, `tools`, `building-blocks`, `orchestration`, `addresses`, `concepts`, `security`, `audit`, `noir`, `testing`, `indexing`, `frontend-ux`, `frontend-playbook`, `qa`, `feedback`. Five more (`contracts`, `defi`, `l2`, `layer2`, and an `openclaw-skill` packaging copy) are 8-line redirects or a re-packaging. They are short: 1837 lines across all of them and the root catalogue together, the longest skill being `crops/SKILL.md` at 258 (`wc -l */SKILL.md SKILL.md`).
- **Routing is a hand-written catalogue plus descriptions.** The root `SKILL.md` is a table of contents: one paragraph and three or four bullet corrections per skill, a "Start here" pointer to `ship/`, and a "What to Fetch by Task" table. Each skill's `description` follows a fixed shape, "Use when ... Not for ... (`/other-skill`)" (for example `orchestration/SKILL.md`, `wallets/SKILL.md`), so the negative clause routes the agent to a sibling.
- **Loading is by URL, or from disk through a plugin.** `README.md` and the homepage (ethskills.com, fetched 2026-10-28) tell the user to give the agent `https://ethskills.com/SKILL.md`, which then fetches `https://ethskills.com/<skill>/SKILL.md` on demand ("Each skill below is standalone. Fetch only the ones relevant to your task", root `SKILL.md`). `vercel.json` rewrites `/:skill` to `/:skill/SKILL.md` and serves `.md` as `text/markdown`. The other install paths are a Claude Code plugin (`.claude-plugin/plugin.json` lists the skill directories, `.claude-plugin/marketplace.json` makes the repo a marketplace), an OpenClaw package (`openclaw-skill/`), a ChatGPT plugin (the `/gpt` redirect in `vercel.json`), and a one-line pointer to paste into `AGENTS.md` or a Cursor rule (homepage, "Persistent Setup").
- **A skill references another by its absolute URL** (`https://ethskills.com/addresses/SKILL.md` in `ship/SKILL.md`) or by `/name` inside a description. It referenced a skill outside ethskills exactly once: `noir/SKILL.md` linked the Noir project's own `noir-idioms` skill (commit `71b8668`, #158, 2026-05-08), and that link was removed when every skill was rewritten in `69dc081` (#173, 2026-10-21).
- **The catalogue is kept by hand in several places, and they already disagree.** The list of skills is repeated in the root `SKILL.md`, the `README.md` table, `.claude-plugin/plugin.json`, `index.html` and `openclaw-skill/SKILL.md`. At `47779e7`, `plugin.json` and the OpenClaw table omit `noir` and `feedback`, which the root `SKILL.md` lists.

## Coverage of deploying

- **Foundry and Scaffold-ETH 2 are the deployment story.** `orchestration/SKILL.md` is "a Scaffold-ETH 2 build leaves localhost": three launch phases with go/no-go conditions, verify right after deploy, rehearse against a fork, never put RPC keys in the committed `scaffold.config.ts`. `testing/SKILL.md` is Foundry. `wallets/SKILL.md` has the key-handling rules (a key seen in a prompt is burned, keys read at run time, "anything that moves funds gets a gate: print the amount, the destination and the gas cost, then stop until a human says yes"). `openclaw-skill/SKILL.md` says "Foundry and Hardhat 3 are both legitimate choices in 2026".
- **hardhat-deploy and rocketh are not mentioned.** `grep -ri "hardhat-deploy\|rocketh"` over every `*.md` at `47779e7` returns nothing. The only mention in the history is one bullet in `tools/SKILL.md` listing `hardhat-deploy` as "advanced deployment management", at `670a151` (2026-02-13), cut the same day by `ec70159` ("pruned to delta-only").
- **One statement is wrong for the Hardhat flavor of Scaffold-ETH 2, which runs on hardhat-deploy v2 and rocketh.** At `87557d9`, `packages/hardhat/package.json` of Scaffold-ETH 2 depends on `hardhat ^3.18.1`, `hardhat-deploy ^2.0.30`, `rocketh ^0.23.1` and `@rocketh/{deploy,node,read-execute,signer,verifier}`; its `deploy/00_deploy_your_contract.ts` is a rocketh `deployScript`; and its `scripts/runVerify.ts` forwards `yarn verify --network <name>` to `rocketh-verify -e <name> etherscan` with a shared key exported from `hardhat.config.ts`. `orchestration/SKILL.md` says, of SE-2 in general, that "`yarn verify` replays `broadcast/run-latest.json`, so run it from the checkout that did the deploy", and that the working key is in `packages/foundry/.env.example`. Both are Foundry-flavor facts. In the Hardhat flavor verification reads the deployment records, which "carry the solc metadata, sources included, so verification can run at any time after the deployment, from any machine that has the records" (rocketh's `documentation/exporting-and-verifying/index.md`).
- **The rest does not contradict rocketh.** The Hardhat-flavor fork facts in `orchestration/SKILL.md` (`yarn fork` forks mainnet, answers chain id 31337, "the chain id never tells you what you forked") match SE-2's `"fork": "MAINNET_FORKING_ENABLED=true hardhat node --network hardhat"` and rocketh's fork documentation (a hardhat fork reports 31337, `documentation/fork-runs/`). What ethskills does not cover is everything rocketh-specific: re-running as the normal path, idempotency from chain state, the unknown-signer pause and its policies, `catchUnknownSigner`, run-once scripts, fork runs that read a network's records without writing them.

## Reuse

- **Licence: MIT, declared but not shipped as a licence file.** `README.md` ends "## License / MIT" and `.claude-plugin/plugin.json` has `"license": "MIT"`. No `LICENSE` file exists in any commit, and the GitHub API reports `"license": null` for the repository (fetched 2026-10-28).
- **The format is modular; what adding a third-party module involves.** A skill is a self-contained directory, loaded only when fetched, so a `rocketh/SKILL.md` would fit the format. Adding one means editing the catalogue in five places (above), passing a contribution bar that every line be a verified blind spot of a stock model or something the human must be taught (`CONTRIBUTING.md`, and `research/triage-methodology.md` in ethskills-research), and accepting wholesale rewrites: `69dc081` replaced all skills with benchmark-refined texts, "5,763 lines down to 889 across the set", tuned against a benchmark held in a separate evals repository (named in the message of `69dc081`, and reachable as `ethskills.com/evals` through the rewrite in `vercel.json`). Its content is served unversioned from `master`.
- **Cited from it: it has been done once.** The `noir-idioms` link (`71b8668`) shows ethskills has pointed at a tool's own skill, and its removal in `69dc081` shows such a pointer was not kept through a rewrite.

## Maintenance

- **Activity:** 142 commits from 2026-02-13 to 2026-10-26, 70 of them in February 2026 and 12 since May (`git log`).
- **Method:** content is added or cut by baseline-testing stock models ("spawn a fresh LLM ... give it a realistic task ... classify each item", `CONTRIBUTING.md`); a full-site review in `audits/2026-03-03-full-site-review.md` checked every address on chain; the October rewrite was benchmarked ("94% vs 85% pass rate", `69dc081`).
- **Automation:** one workflow, `.github/workflows/update-gas.yml`, which weekly rewrites the "Last verified" gas and price stamp in `gas/SKILL.md`. Nothing tests a code sample against a library.
- **Feedback:** `feedback/SKILL.md` asks the agent to POST a note to `https://ethskills.com/api/feedback` (`api/feedback.js`).
- **Listing:** ethereum.org lists it under Agent tooling ("Listing reviewed March 2026", 301 stars, fetched 2026-10-28).

## What the agent skills format and tooling provide (read for distribution)

- agentskills.io/specification: a skill is a directory with `SKILL.md`, frontmatter `name` (lowercase and hyphens, equal to the directory name) and `description` (up to 1024 characters, "what the skill does and when to use it"); optional `references/` loaded on demand; keep `SKILL.md` under 500 lines.
- The skills CLI (`npx skills add <owner>/<repo>`, docs/creating-skills.md) discovers `skills/<name>/SKILL.md` in a repository, so this repository's existing `skills/` folder is already installable that way. Its experimental `skills experimental_sync` (docs/commands.md) finds `skills/<name>/SKILL.md` inside an installed npm dependency and links it into `.agents/skills/` and the agents' own folders, "so they update with the dependency".
