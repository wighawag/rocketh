# The deployment record is a published format, with a listed schema and a stability promise

The deployment record, the JSON content of `deployments/<environment>/<Name>.json` that `env.save` writes (`packages/rocketh/src/environment/index.ts:1142-1192`) and that `env.get`, `@rocketh/export`, `@rocketh/verifier`, `@rocketh/proxy` and `@rocketh/diamond` read back, is a PUBLISHED format (maintainer decision, 2026-09-24). Its type cannot say what is promised, because `Deployment` ends in `& Record<string, unknown>` (`packages/rocketh-core/src/types.ts:576-605`) and `@rocketh/diamond` writes a field the type does not declare (`facets`). So the list below is taken from the WRITE sites, and it is the list, not the type, that users may hold the project to.

Two rules divide the work. ADR 0012 governs what a field may ASSERT: only what rocketh observed, as of the run that wrote the record, never the chain at read time. This ADR governs whether a field's PRESENCE and NAME are promised.

## The promise

For every field in the table below: **it is not removed, renamed, or given a different meaning in any 0.x release.** Today every package is 0.x, and the release tooling deliberately keeps it there (a guard refuses graduating to 1.x), so "without a major version" would promise nothing; instead the listed fields are FROZEN for the whole 0.x line, and such a change can only come with 1.0 or a later major. The promise binds the package that WRITES the field: `rocketh` for `address`, `transaction`, `receipt` and `numDeployments`; `@rocketh/deploy` for the fields it assembles (`argsData`, `libraries`, `linkedData`, and the ones copied from the artifact); `@rocketh/diamond` for `facets`; `@rocketh/proxy` for `implementation` and for what it writes onto a proxy's `<name>` record. Adding a field is not breaking. Turning an "always" field into an optional one is a removal for the records that lose it, so it is breaking. rocketh keeps reading records written by any earlier 0.x version (an absent `numDeployments` reads as 1, for instance).

This is the maintainer's current policy, decided 2026-10-26. If it changes, it changes through a new ADR that supersedes this one and is published before the release that relies on it; a release never weakens it silently.

**Absent means absent.** An optional field that has nothing to say is omitted from the file: never written as `null`, an empty string, or an empty placeholder array. `numDeployments` is the existing instance of the rule (omitted while it is 1, `index.ts:1176-1183`).

## Written today, promised nothing

- **The open tail stays.** `& Record<string, unknown>` remains so extensions and user scripts can `env.save` extra fields. Such a field is promised NOTHING unless this ADR lists it: no stability, no read-back, not even preservation (rocketh's own rewrites rebuild a record from parts, e.g. `rocketh-proxy/src/index.ts:706`, and drop what they do not carry). A future rocketh field may take any unlisted name, so an extension that wants to avoid a collision should namespace its key.
- **Artifact pass-through keys.** Anything else an artifact carries rides through the spread. Concretely, records built from the vendored v1 artifacts (proxy contracts, default diamond facets) carry `solcInput` and `solcInputHash`; the `_`-prefixed keys are stripped only on the broadcast path (`index.ts:1482-1485`), not at the `env.save` call sites.
- **`newlyDeployed`** leaks into a diamond `<name>` record on its fresh-deploy path, because `rocketh-diamond/src/index.ts:463-466` spreads the `DeployResult`. It is a run result, not record data, and is not part of the format.

## Not carried

v1 fields deliberately absent, reasons in `work/notes/findings/hardhat-deploy-v1-feature-surface.md` section H: `history` (`numDeployments` carries it, `rocketh-proxy/src/utils.ts:29-32`), the full `receipt` (ADR 0012), decoded `args` (`argsData` supersedes it), `solcInputHash` (metadata carries literal sources; its pass-through above is not a promise), `methodIdentifiers` (dropped 2026-09-24), `factoryDeps` (zkSync, `work/notes/ideas/zksync-support.md`). Also NOT carried: the `execute` option a diamond was deployed or cut with, which v1 and early rocketh echoed onto the diamond record; it asserted nothing (it was rewritten on runs where no init ran), nothing read it, and it stopped being written before this ADR (#189). Also NOT planned: script `tags` / `dependencies` on records, whose task was cancelled (`work/notes/ideas/tag-recording-and-selective-reset.md`).
